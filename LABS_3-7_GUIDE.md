# Як додати та здати лабораторні 3–7

Усі роботи виконані для варіанта 7. Старі роботи в архів не включені.

## Завантаження на GitHub

1. Розпакуй архів через «Видобути все». Відкрий розпаковану папку.
2. Відкрий https://github.com/Yariker9039/OOP-Zahorovskiy у своєму акаунті.
3. На вкладці Code натисни Add file → Upload files.
4. Перетягни шість папок lab3v7, lab6v7, lab8v7, lab10v7, lab12v7, lab12v7.Tests, а також README.md і LABS_3-7_GUIDE.md. Сам ZIP завантажувати не потрібно. Зовнішню папку архіву також не перетягуй.
5. У полі повідомлення коміту напиши: Додано лабораторні 3–7, варіант 7.
6. Натисни Commit changes. README.md у корені оновиться, а старі роботи залишаться.
7. Перевір, що нові папки лежать поруч із lab1v7 і lab2v7.

## Що здавати

У завданні Classroom натисни «Додати або створити» → «Посилання», встав посилання на репозиторій та натисни «Здати». Вкажи потрібну папку у коментарі:

- Лабораторна 3 — lab3v7; звіт REPORT.md.
- Лабораторна 4 — lab6v7; звіт README.md.
- Лабораторна 5 — lab8v7; звіт README.md.
- Лабораторна 6 — lab10v7; звіт README.md.
- Лабораторна 7 — lab12v7 та lab12v7.Tests; звіт README.md.

Назви папок здаються дивними, але саме такі вказані в методичках. Для робіт 4–7 методички дозволяють звіт у README. Для роботи 3 REPORT.md містить повний код, результат і висновок.

## Як запустити

Потрібен .NET SDK 10, як у попередніх роботах. У Visual Studio відкрий .csproj потрібної роботи та натисни Ctrl+F5. Або відкрий термінал у папці репозиторію й виконай команди з головного README.

Для тестів: dotnet test lab12v7.Tests
Під час першого запуску тестового проєкту потрібен інтернет для завантаження пакетів xUnit.

## Коротко для захисту

3. Я імітую COM-порт. Using сам викликає Dispose. Явний Dispose роблю вручну. Фіналізатор показую через GC.Collect і очікування завершення. У звичайній програмі на час фіналізатора покладатися не варто.

4. Person зберігає спільні дані. Student і Professor перевизначають Greet. Override вибирається за реальним об’єктом, а new — за типом змінної. Через це GetRole для одного студента дає два різні результати. Ланцюжок Professor від Student узято буквально з методички; у реальній моделі це було б спірним рішенням.

5. Я поклав три різновиди повідомлень в один List<Notification>. Один цикл викликає їхні Send, потім виводить усі тексти. Ніяких справжніх SMS чи листів програма не надсилає.

6. INotifier задає спільну дію. Authenticator ще має готовий LogAttempt, щоб не дублювати код. Перевірка користувача своя в кожному класі. База та LDAP тут імітуються тестовими словниками.

7. T — тип елемента репозиторію. Where T : IEntity гарантує Id. Репозиторій зберігає відділи в списку та виконує CRUD. Якщо Id відсутній, викидається KeyNotFoundException. 12 тестів перевіряють правильні дії та помилки. Перед захистом запусти тести й подивись RepositoryTests.cs.
