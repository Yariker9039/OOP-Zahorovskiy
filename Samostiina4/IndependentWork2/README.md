Тема: перевантаження конструкторів.

Проєкт названо IndependentWork2, як прямо вказано в завданні №4. Він розміщений в окремій папці Samostiina4, щоб не конфліктувати із самостійною №2.

Запуск з кореня: `dotnet run --project Samostiina4/IndependentWork2`.
Фактичний вивід: `console-output.txt`.

## Реалізація

Product має п’ять приватних readonly полів та п’ять публічних властивостей без set: Id, Name, Price, Category, StockCount. Основний конструктор задає всі поля. Скорочений викликає його через this і підставляє Uncategorized та 0. Конструктор копіювання також викликає основний, передаючи дані оригіналу. ToString повертає всі п’ять характеристик, ціну відформатовано через :C для uk-UA.

У Main створено рівно три товари. ReferenceEquals показує False: копія — окремий об’єкт із тими самими даними. За умовою копіюється і Id. Тому цей приклад не забезпечує глобальної унікальності Id між копіями; у реальному каталозі створення нового товару за копією потребувало б окремого нового ідентифікатора.

## Контрольні запитання

1. Перевантаження дозволяє створювати товар із повними даними, лише з основними даними або за іншим товаром.
2. This передає ініціалізацію та перевірки основному конструктору. Не потрібно дублювати присвоєння п’яти полів.
3. Відсутність set захищає дані від змін після створення; readonly додатково обмежує присвоєння полям у самому класі.
4. ToString дозволяє передати об’єкт у Console.WriteLine й одразу побачити його дані, що зручно для демонстрації та налагодження.

## Висновок

Три способи створення використовують єдине місце ініціалізації. Ланцюгові виклики зменшують дублювання коду, а властивості лише для читання зберігають стан товару після створення.
