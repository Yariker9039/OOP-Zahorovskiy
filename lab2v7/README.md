# Лабораторна робота №2 — варіант 7

Загоровський Ярослав Віталійович, ІПЗ 3/1.
Тема: клас із кількома конструкторами та життєвий цикл об’єкта.

Код: [Phone.cs](Phone.cs), [Program.cs](Program.cs). Звіт із повним кодом і результатами: [REPORT.md](REPORT.md).
Запуск з кореня: `dotnet run --project lab2v7`.

Phone має поля _brand, _model, _batteryLevel. BatteryLevel приймає лише значення від 0 до 100. Конструктор без параметрів викликає параметризований через this("Generic", "Basic", 50). Call зменшує заряд на 1, якщо телефон не розряджений. Фіналізатор виводить повідомлення.

У Main через допоміжний метод створено три телефони. Окремий метод із NoInlining потрібен, щоб перед GC локальні посилання більше не утримували об’єкти; це особливо важливо під час налагодження. Порядок повідомлень фіналізаторів не гарантований.

## Контрольні запитання

1. Перевантаження — кілька конструкторів із різними параметрами. Воно дає змогу створити телефон із типовими або власними характеристиками.
2. This викликає інший конструктор цього класу. Спочатку виконується параметризований конструктор, потім тіло конструктора без параметрів.
3. Фіналізатор виконується середовищем .NET для недосяжного об’єкта з фіналізатором. Звичайний час і порядок не визначені; виконання перед завершенням процесу не гарантовано.
4. GC.Collect може створити зайву роботу та паузи. Зазвичай середовище саме обирає час збирання; тут ручний виклик потрібен лише для навчального експерименту.

## Висновок

Конструктори задають коректний початковий стан, а this дозволяє повторно використовувати ініціалізацію. Після втрати досяжності об’єкт може бути фіналізований і згодом зібраний GC. Вихід із методу сам по собі не означає негайного виконання фіналізатора.
