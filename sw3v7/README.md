## Реалізація

SerialPortConnection імітує серійний порт полями _portName та _isPortOpen. Це не підключення до обладнання. Публічні властивості показують назву та стан. Метод SendData виводить байти, перевіряючи, чи об’єкт не звільнено.

Реалізовано IDisposable, публічний Dispose(), protected virtual Dispose(bool disposing), деструктор із Dispose(false), GC.SuppressFinalize(this) і прапорець _disposed. У класі немає керованих ресурсів, що потребують Dispose; місце їх звільнення позначено коментарем лише у гілці disposing == true.

## Три сценарії

1. COM1 використовується в using. Після виходу з блоку Dispose викликається автоматично, у тому числі при винятку всередині блоку.
2. Для COM2 Dispose викликається явно. Повторний виклик нічого не робить. Спроба SendData після звільнення породжує ObjectDisposedException, який демонстрація обробляє.
3. Для COM3 Dispose не викликається. Після прибирання посилання GC.Collect запускає збирання, а GC.WaitForPendingFinalizers очікує фіналізатор, який викликає Dispose(false).

## Висновок

Using забезпечує своєчасне автоматичне звільнення ресурсу наприкінці блоку. Явний Dispose теж звільняє його одразу, але програміст має подбати про виклик, зокрема при винятках. Фіналізатор є резервним механізмом: у звичайній програмі час його виконання не визначений і він може не встигнути виконатися перед завершенням процесу. Примусовий GC застосовано лише для демонстрації.

## Контрольні запитання

1. Життєвий цикл: створення та ініціалізація, використання, втрата досяжності, можливе виконання фіналізатора та подальше збирання пам’яті.
2. Керована пам’ять обліковується GC. Некеровані ресурси, наприклад дескриптор ОС, потребують окремого звільнення; GC сам не знає правил їх закриття.
3. IDisposable визначає метод Dispose для явного звільнення ресурсів. Сам виклик Dispose не видаляє об’єкт із пам’яті.
4. Using гарантує Dispose при виході з області використання, фактично організовуючи try/finally.
5. SuppressFinalize прибирає потребу у фіналізації об’єкта, ресурс якого вже звільнили.
6. Dispose(true) дозволяє звільнити керовані та некеровані ресурси. Dispose(false) призначений для фіналізатора: не слід покладатися на придатність інших керованих об’єктів для звільнення. Консольний вивід тут залишено для навчального спостереження.
